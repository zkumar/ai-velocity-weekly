04 · WHERE THE YES IS KEPT

The Store, the Call Id and the Node Behind an Approval

All three executed on both versions. The owner-scoped approval is executed on slide 08.

MICROSOFT · AGENT FRAMEWORK 1.20.0EXECUTED

A forged request and its own approval submitted a prior auth on 1.19.0

PR #8750 moves approval authority into the AgentSession. On 1.19.0 a caller-supplied history holding an approval request the framework never issued, plus its approval, ran the tool for pt-999. On 1.20.0 it is dropped with one WARNING. So is a genuine approval replayed with no session: nothing submitted, an empty reply, no exception.

What changed

The transcript stopped being an authority. A stateless approval service that replays the conversation now resumes nothing, and says nothing.

What to change

Persist the AgentSession and pass the same one to the resuming run, alert on the warning text, and leave disable_approval_response_binding unset: with it the forged request ran again.

Read the mechanism

PYDANTIC-AI 2.53.0EXECUTED

One tool_call_id on two calls: the chart read never ran and the submission ran twice

A response carrying read_chart and submit_prior_auth under the same id. On 2.52.0 the last call won the binding for both: submit_prior_auth executed twice, read_chart zero times, and the model was handed a synthesised "interrupted" return for the chart. On 2.53.0 the batch raises UnexpectedModelBehavior before any call executes.

What changed

A repeated id is a hard failure instead of a mis-bound result, and a new exception on the request path.

What to change

Catch UnexpectedModelBehavior, log the raw response and do not retry blindly. Below 2.53.0 behind any gateway that rewrites ids, count submissions against requests.

Read the mechanism

GOOGLE ADK 2.11.0EXECUTED

require_confirmation on a workflow tool node pauses, where 2.10.0 returned an error string

A two-node workflow with no model. On 2.10.0 the gated node's output was "This tool call requires confirmation, please approve or reject.", the workflow finished and nobody was asked. On 2.11.0 it emits adk_request_input with an id built from the node path, runs nothing until a confirmed response arrives, then submits once.

What changed

A gate that failed safe and silent became a request with a stable id. The response carries a boolean and no approver.

What to change

Store the request id beside the approver's identity yourself, and search 2.10.0 workflow outputs for the confirmation error: each one is a submission that never happened.

Read the mechanism

ARCHITECT SIGNALNone of the three needs a code change on your side to take effect. One turns a working resume into a silent no-op and one adds an exception, so a warning text and an exception class belong in monitoring before the pin moves.

05 · WHAT THE LIST AND THE LOG OMIT

A Callable Tool Off the List and a Transcript the API Refuses

One executed, one read from the vendor's documentation. Each is a store that was treated as complete or portable.

MCP PYTHON SDK 2.3.0EXECUTED

lookup_claim was missing from list_tools() and ran when called by name

A tool registered with the header annotation "Member Id", invalid because of the space. On 2.2.0 the server accepted it, the client listed zero tools, and call_tool executed it and returned two open claims. On 2.3.0 registration raises InvalidSignature and the call returns "Unknown tool".

What changed

The listed tools and the callable tools were different sets. An allow-list or a per-tool policy built from the list never covered the hidden one.

What to change

On 2.2.0 servers, compare the tools registered on the server with what a client lists, then upgrade so a bad annotation fails at start-up.

Read the mechanism

ANTHROPIC · CLAUDE SONNET 5.5 APIDOCS

Forced tool choice returns 400, and so does a thinking block replayed after the prompt changed

tool_choice of any or tool "returns a 400 invalid_request_error" on this model. Thinking blocks are checked against what preceded them: change the system prompt, the tools or an earlier message and a replay returns 400, by default for accounts created on or after 31 August 2026. Blocks work only in the account that produced them.

What changed

A stored transcript is not portable across a prompt edit, a tool change or a redaction, and a forced structured call is not available.

What to change

Keep the deployment version with every paused state and resume against it. Move forced-tool extraction to auto with strict schemas, and test that the tool is still called.

Read the mechanism

ARCHITECT SIGNALAn inventory read from the client and a transcript kept for replay both went stale with no error at write time. Reconcile each against its source on a schedule, not at the audit.

07 · PAPERS TO IMPLEMENTATION

The False Success, the False Accusation and the Encounter Nobody Scored

Three results on success claimed after a failed tool, correct work undone on an unsupported complaint, and accuracy that hides a failed encounter. Each is the authors' own measurement.

FAILURE-TRANSPARENT AGENTS · 2609.35732

False success after a failed tool: 22.8% at baseline, 0.8% under an evidence contract

100 tasks with the failed observation fixed before generation, six models, 3,600 human-annotated responses. A transparency instruction alone gives 9.3%. Fabricated detail falls from 28.3% to 14.3% to 0.8% across the three policies, while useful responses rise from 74.9% to 98.8%. The benchmark is the authors' own blocked-task set.

What changed

An instruction to be honest still leaves about one false success in eleven. A structured contract leaves fewer than one in a hundred.

What to change

Require every completion claim to carry the tool call id and the returned status, and have the harness reject a "done" without them.

Read the mechanism

CAVE-BENCH · 2609.32616

Told falsely that finished work was wrong, agents damaged it in up to 60% of runs

365 tasks across six domains where the work is verified correct and the accusation cannot be checked locally. Across 14 models in one coding harness, false accusations damaged correct work in up to 60.06% of runs, stronger models often after recovering the supporting evidence. A harness gate cut replayed harm by 74%. Software tasks, not clinical.

What changed

After compaction or a handoff, a complaint about completed work is an input the agent tends to obey.

What to change

Put the amend tool behind its own gate, and route an unsupported complaint about a completed write to a person with the evidence attached.

Read the mechanism

KLINIKEBENCH · 2609.38480

90.7% diagnostic accuracy, and fewer than 30% of encounters completed correctly

333 clinician-authored sandbox tasks with a virtual patient, clinical tools and action constraints, more than 35 clinicians involved. Across 31 models the best succeed on fewer than 30% of tasks while their diagnosis accuracy reaches 90.7%. History taking, examination requests, constraints and the final record are scored separately and together.

What changed

Final-answer accuracy is no longer evidence that the encounter was conducted properly.

What to change

Gate releases on every step passing, constraints included, and report the diagnosis score beside the whole-encounter score, never alone.

Read the mechanism

ARCHITECT SIGNALA claim, a complaint and a score each looked like evidence and was not. Whatever reaches the record should cite the result it rests on, and the citation is what the harness checks.

08 · MECHANISM OF THE WEEK

The always that followed a tool name across a handoff

OPENAI AGENTS SDK 0.23.1 · SCRIPTED MODEL, 0.22.3 AGAINST 0.23.1, NO MODEL KEYEXECUTED

Two agents, intake and anticoagulation, each own a tool named place_order behind an approval gate. The scripted model has intake order a saline flush; the nurse answers "always approve"; the run hands off and the second agent orders warfarin 10 mg. On 0.22.3 the nurse was shown one order and two reached the record. On 0.23.1 the warfarin call interrupted and one order was written. On both versions the same always also covered heparin 5,000 units from the same agent, in process and after a JSON round trip.

What changed

The sticky approval was keyed by tool name. It is now keyed by owning agent and tool name, and saved run state moves to schema 1.18. Neither key contains an argument.

Move

List every tool gated with always_approve and remove it wherever the argument carries clinical meaning. Search order history for writes by one agent under a sticky approval granted to another. A paused run saved after a sticky yes on 0.22.3 came back on 0.23.1 asking for the approved call again, so drain paused runs before rollout.

09 · WHAT THE ARCHITECTS SHIPPED

Technical output only, no job moves

  • GOOGLEADK 2.11.0 adds an optional ToolCallIntegrityPlugin that stamps each stored function call with an HMAC and lets a tool run only on a valid stamp, plus plugin callbacks around workflow tool nodes. The first shipped control for a call altered after approval.
  • MICROSOFTAgent Framework 1.20.0 also gives generated MCP calls host runtime context only, "never model arguments, even when names collide", and pickles dict subclasses in checkpoints, so 1.19.0 and 1.20.0 encode the same state differently.
  • OPENAIAgents SDK 0.23.0 binds resumed MCP calls to their original recipients and leaves reasoning out of default trace exports. The Python SDK adds session traces, and the Agents API gains computer use.
  • ANTHROPICSDK 1.10.0 adds a refusal stop reason and stop_details to Managed Agents idle events, so a session that stopped on a refusal can be told from one that finished, and refuses credential files that group or others can write.
  • AI HEROMatt Pocock's newsletter of 1 October announces a guardrail that blocks destructive git commands before a coding agent runs them. Read from the email only, so UNVERIFIED: a deterministic check in front of an irreversible tool.

Nothing in window from the MCP specification or blog, LangGraph, llama-index-core, Semantic Kernel, NVIDIA healthcare or Epic. FHIR R6 is not final. No HTI-5, TEFCA, HIPAA Security Rule or physician fee schedule final rule appeared. Nebius published Q3 notes with a stateless Responses API.

10 · CONSTRAINTS AND RADAR

Change Control Gets a Fiscal Year and Trials Get an Agent Layer

FDA · CDRH FY2027 PROPOSED GUIDANCES, DOCKET FDA-2012-N-1021

The AI lifecycle and change-control guidances are on the list FDA intends to publish as final this fiscal year

The A-list, "priority guidance documents CDRH intends to publish during FY 2027", holds the final AI-enabled device software functions guidance, the final predetermined change control plans guidance, and a draft on generative-AI conversational devices for mental disorders. Comments on the list close 30 November.

Move

Three of this week's upgrades changed when a human is asked. Under a final change-control guidance that is a change to describe in advance: write the protocol now, with pinned versions, the tests that must pass before a pin moves, and who signs.

HHS · ARPA-H · SURPASS

A national trial platform will "create an agentic operations layer", and names no provenance format

Launched 30 September. The layer is to automate trial startup, onboarding of new treatment arms and "data collection, cleaning, and dataset construction"; a companion project is to "enable access to regulatory-grade data". No funding figure is given, and nothing says what record shows which values an agent changed and on whose authority.

Move

An agent that cleans trial data writes to a record a regulator reads. If you bid, bring the provenance record with the proposal, before the platform defines a log without one.
